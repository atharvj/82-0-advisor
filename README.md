# 82-0 Perfect Team Coach

A userscript for [82-0](https://82-0.com/) that recommends the best player, exact position, lineup moves, and retries in Classic, Hoop IQ, and 1v1.

## Install

1. Install Tampermonkey or Violentmonkey.
2. Create a new userscript and paste in [`82-0-advisor.user.js`](./82-0-advisor.user.js).
3. Save it, refresh 82-0, and start a new game.

Version 2.9.0 adds a **self-contained stats fallback for Hoop IQ**: 10,626 reference peaks across 180 team/era pools, including all 73 GSW 1990s players. It retains **numbered lineup instructions**, including every prerequisite move needed to free a blocked position and the final player placement. These appear for direct picks and for the alternative pick when a retry is recommended. **Owned tokens and ad retries are evaluated alongside free retries**, while coin/purchase-only options get clearly labeled conditional estimates. Missing or configuration-only counters no longer mean zero retries. Partial session updates refresh funding labels; stale responses cannot restore spent retries from an older cell. Highest expected final score remains the objective in every mode and supported API version. The full live planner still runs in a background worker, with a draggable panel and synced pop-out window. It retains **full roster-position flexibility** on the October 2026 API v4 site. Jersey initials such as Paul George's “PG” are not mistaken for his court position. Occupied jerseys remain tracked when selecting a player turns them into non-interactive elements, and advice is validated against the current lineup before displaying a pick.

On v4, a finite-horizon dynamic program compares picking now, rerolling Team, and rerolling Era. Its state retains every legal occupied-position arrangement for the selected players, including hypothetical future selections. A PG/SG placed at PG therefore does not permanently block a future PG: the planner knows that player can move to SG. Future-roll estimates start with 69 anonymously observed team/era pools and incorporate stats for actual rolls encountered in your browser (including recovered Hoop IQ offers). The entire reference catalog is not assumed to be a future server offer. Sparse Team/Era samples are smoothed toward the overall sample to limit overconfidence.

With two picks remaining, the planner evaluates completed five-player scores directly over sampled future offers, including exact recorded-defense normalization and excluding the current incoming player's name from the last offer. The last pick maximizes the calculated completed-team score across players who can fit after legal rearrangement. Early-round forecasts still approximate defensive-stat counts and hypothetical future player-name collisions.

These are **sample-based recommendations, not guaranteed optimal choices or guaranteed 82-0 runs**. The server hides future offers and the full current database, and its score-to-record conversion changed on v4. The coach therefore does not invent final-win forecasts or claim to prove 82-0 is impossible on v4. Actual picks remain restricted to the live offer. Older dataset-based sites retain their optimizer but now rank choices and retries by score, not sampled bot-win or 82-win probability.

The visible **82-0 outlook** says **likely possible · estimate**, **unlikely · estimate**, or **uncertain** in Classic, Hoop IQ, and 1v1. On v4 this is a score-based heuristic, not a measured success probability: it compares the expected final score with a provisional 110-point planning benchmark, refining that reference with recent official v4 records saved in this browser. The exact current server cutoff is unverified; the old score-to-wins curve is not reused. Hover the indicator or open **Why this choice?** to see the forecast and reference. Unknown offered-player stats, too few planning pools, or contradictory record observations make the outlook uncertain. A poor forecast or no successful samples never proves impossibility. **Impossible** is reserved for verified complete-dataset/exact-seeded bounds on older supported sites, and advice continues regardless of the outlook. Outlook labels do not influence pick or retry ranking.

Hoop IQ omits stats from its server responses. The coach now matches hidden stats by **player + franchise + era**, using actual game data first, previously observed Classic stats second, and the bundled reference last. The [public factual stats snapshot](https://82-0.vercel.app/players.json) was checked on October 10, 2026 against all 479 saved Classic samples; fresh Classic checks also confirmed matching values. It is a reference snapshot, not proof that every current server row is unchanged. Accent/punctuation variants and historical franchise abbreviations are supported, but different teams/decades are never interchangeable and conflicting name matches are rejected. The current game supplies player identities and position eligibility; the reference never introduces absent selectable players. **Reference stats** is shown when a suggestion uses the bundled fallback, and current Classic observations supersede it—including for an already picked matching peak. No Classic warm-up games or extra runtime network requests are required for covered players.

Unknown stats remain clearly reported rather than guessed or filled with zero. A recommendation based on only part of an offer is labeled accordingly. If every offered player's stats are genuinely unmatched, the coach does not advise burning retries just because it cannot score the offer, and its outlook stays uncertain. Newly added or changed peaks may require actual Classic observations or a reference update. No player data or history is uploaded, and the coach never changes the game's hidden-stats display.

The coach is advisory only and panel-only: it reads the draft state but never outlines, relabels, disables, or otherwise modifies the website's player cards, positions, and retry buttons. All instructions appear in the side panel. Use the `⏻` button in its header to turn the coach off for as many games as you want; the small **Coach off** pill remains available to turn it back on.

When a pick needs multiple lineup moves, the coach shows a numbered list naming **each player, their starting position, and their destination**, followed by the incoming player's placement. Follow the list in order: each destination is empty at that step, even if another player must move first to free it. It never begins with an occupied-position swap. Completed moves disappear as the route is rechecked against the current lineup. **MOVE FIRST** lists are visible without opening details. If a free/owned retry is recommended, open **Why this choice?** for the alternative pick and its complete lineup steps; purchase-only advice keeps its no-purchase alternative visible. This is shared across Classic, Hoop IQ, 1v1, and older supported site versions. Improving the complete team remains the priority, with fewer moves preferred on equal-score routes; the display change does not change the scoring algorithm or reduce planning accuracy.

Current v4 recommendations use the live offer directly and do not wait for a missing dataset. The live planner runs off the page's main thread, including the heavier exact two-pick scoring, so the site remains responsive while analyzing. It uses the same planner code, pools, scoring, and tie-breaks as the previous synchronous implementation—no shortened calculation, reduced samples, or weaker interim picks. Obsolete calculations are cancelled when the roll or lineup changes, the game finishes, or the coach is turned off. If the browser blocks workers, the coach falls back to the unchanged full calculation; that fallback can still pause the page. Animated dots beside **Analyzing the roll** indicate a pending calculation.

Drag the coach by its header to reposition it within the page; the position is remembered locally and kept on screen when resizing. Click **↗** to open a separate synced coach window, then drag that window's native title bar onto another monitor. Allow pop-ups for 82-0 if prompted. Click **↩** in either window to dock the coach back in its default corner. Closing the separate window restores the page panel automatically. Keep the game tab open: it supplies the live state and runs the calculations, and closing or navigating away from it closes the coach window. These controls only affect the coach, never the site's cards or buttons.

In 1v1, the coach shows the bot's target score when supplied by the session, but **the bot's score never changes the score-maximizing objective**. A higher expected final score is preferred even if a lower-scoring strategy has a higher sampled bot-win probability. The final panel compares the two scores when available. It does not claim a guaranteed win.

Live browser 1v1 was verified on October 9, 2026 through Classic's `opponent=bot` variant. Userscripts run in the browser and cannot run inside the native app.

On October 10, 2026, a fresh anonymous live Hoop IQ game (`mode=hoopiq`) returned no stats for its 68 MIN 1990s players. With an empty browser cache, the coach recovered all 68 from the reference and displayed a legal player/position recommendation. Full GSW 1990s coverage and cross-mode retries are also covered by automated tests.

Every live recommendation is restricted to the exact player squad returned by the server for that roll. In 1v1, known bot-owned players are excluded from planning samples when their identities can be matched. Historical planning samples never introduce a selectable player who is absent from the actual offer.

Forecast records are expected values used for planning. Because 82-0's returned result is authoritative, the coach reads and displays the result shown by the site on the final screen. It also stores up to 100 anonymous results locally in the browser and shows the current version's average and best result, making strategy changes measurable without uploading any history.

## Guide

- Green panel: pick this player
- Blue panel: make the displayed position move
- Orange panel: Team retry
- Purple panel: Era retry
- Red panel: final non-perfect result or lost matchup; older full-dataset versions also report impossible ceilings

Retry advice takes priority in the panel, in orange for Team and purple for Era. It never changes the website's button labels or blocks your picks. The compact **Team / Era** line shows the funding source (**free**, **owned token**, **watch ad**, **coins required**, or **purchase option**) and estimated score gain. An enabled button can open a shop rather than grant a free retry. When a purchase would improve the forecast, the panel says **CONSIDER RETRY**, explicitly warns that buying is required, and keeps the best no-purchase option visible (a pick or a different usable retry). Purchase quotes show buying one retry now versus picking without buying, but a purchase is recommended only if it also beats any usable retry. They do not assume affordability, future purchased inventory, or improve the 82-0 outlook before a purchase. Missing funding metadata is labeled **available · check cost**, never falsely advertised as free. The coach never buys anything, watches ads, or consumes tokens for you.

Live planning models the next usable retry of each type, comparing rerolling now with picking and keeping it for future rolls; it does not model an unlimited supply or every extra token you might own. Not rerolling can be correct even when a retry remains. The coach observes `disabled`/`aria-disabled` changes as well as text changes, so temporary animation lockouts show **not ready** rather than claiming the retries are spent. Open **Why this choice?** for fuller forecasts and the planning sample count. Hover the coach title or open details to confirm the installed version. Press `Alt+A` to hide or restore the coach.

## Validation

Run `node tests/core.test.js`, `node tests/hidden-stats.test.js`, `node tests/retries-outlook.test.js`, `node tests/live-worker.test.js`, and `node tests/live-planner.bench.js`. Tests compare compact roster eligibility with exhaustive assignment, exercise move-route progression, and check exact two-pick scoring and duplicate exclusion. Hidden-stat tests cover the complete GSW 1990s pool, source precedence, exact peak matching, spelling variants, null/zero handling, eligibility preservation, and no invented players. Retry/outlook tests verify score-first ranking over bot-win rates, funding-source detection, partial metadata, conditional purchase safety, and conservative outlook labels. Worker tests compare 91 full recommendations with the synchronous planner across funded/purchase retry combinations and pick stages, and verify that the calling event loop keeps running. The benchmark compares greedy/no-retry, v2.5 fixed-slot planning, and current flexible-roster planning across 500 paired simulated drafts from captured rolls. It is a regression test of the sampled model, **not a real-game win-rate claim**. Live Classic tests also verify selectable recommendations, position tracking, retries, and reading the site's final result.

Optional UI regressions: with Playwright and its Chromium browser installed, run `node tests/panel.browser.test.js`, `node tests/retries.browser.test.js`, `node tests/lineup-steps.browser.test.js`, and `node tests/hoopiq-stats.browser.test.js` (or set `PLAYWRIGHT_MODULE` to an existing Playwright module path). Local fixtures test background calculation, cancellation, blocked-worker fallback, dragging, viewport clamping, reset, pop-out syncing, docking, closing, and blocked pop-ups. Cross-mode fixtures verify both retry kinds, attribute-only animation completion, free/owned/ad funding, conditional purchases and coin caps, partial/stale metadata, reference-stat recovery with an empty offered-player cache, source labels, wire/cache precedence, no external requests, 82-0 outlook, bot-independent score-first decisions, and full four-move lineup chains that shorten as moves are completed, without making game API requests.

To refresh the embedded factual reference, run `node scripts/update-reference-stats.js --date=YYYY-MM-DD` after checking current Classic rolls. The generator downloads the public snapshot, checks all saved samples, rejects malformed stats, and updates only the marked reference block using `apply_patch`. It does not execute third-party code. Review the data/version changes and rerun tests before publishing; updating the reference does not update the userscript version automatically.
